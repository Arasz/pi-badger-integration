## 2. PKG-A — pure failure matcher (`extensions/router-fallback/router-fallback-core.ts`)

**Shape:** copy `/Users/arasz/RiderProjects/pi-badger-integration/.ai-badger/worktrees/pbi-router-failure-free-model-fallback/extensions/monitor/monitor-core.ts` purity rules (only pure imports, injected `now`, no fs/net/pi). No `node:vm` needed — matcher is regex/prefix, not predicates.

**A1. `classifyFailure(input) → {kind: "billing-exhaustion" | "throttle" | "auth" | "model-unavailable" | "not-fallback"}`**
- Inputs: `{errorMessage?: string, afterProviderStatus?: number}`. Rules: (a) status-prefix parse on `errorMessage` (`/^\s*(\d{3})\s*:/` — the `formatProviderError` shape); (b) billing-substring set = the 8 non-retryable strings from `retry.js:4-18` **plus** OpenRouter-documented `payment_required` / `insufficient credits` / `rate_limit_exceeded` / `authentication` (d-487 §4); (c) overflow pre-check — if message matches the installed `isContextOverflow` patterns for the active model, return `not-fallback` before anything else (mirrors `agent-session.js:2248-2252`).
- Decision table: `billing-substrings present OR status-prefix 402` → `billing-exhaustion` (fallback); `401/authentication` → `auth` (fallback only if another configured provider exists — else notice-only); `429/rate_limit` without billing text → `throttle` (cool-down current provider, do NOT switch model family — seam to PKG-C); `503/no-provider` → `model-unavailable` (switch model within same provider, seam to PKG-C); `400/403/404` → `not-fallback` always (d-487 §5); 200-with-`error`-body and SSE `finish_reason:"error"` are already folded into `errorMessage` by `openai-completions.js:497-527`, so no separate SSE scanner is needed in the extension — **this is the simplification adopted** (see §5).
- AC: every d-487 verbatim payload (429 envelope, SSE error chunk, 402 reconstruction, 401, 503) classifies per table; 400/403/404/context-overflow never classify as fallback. Gate: `tests/router-fallback/router-fallback-core.test.ts` green + `bunx tsc --noEmit -p .` green.
- Tests (failure mode → proving mutation): (i) 402-with-billing-text missed → drop `billing` from pattern, test must redden; (ii) 429-with-`insufficient_quota` misread as throttle (order bug) → swap non-retryable/retryable check order, must redden (pins `retry.js:171-173` ordering); (iii) exact-JSON brittleness → append whitespace/metadata field to fixture body, must stay green (pins substring-not-exact rule); (iv) overflow mis-fallback → feed OpenRouter `maximum context length` fixture, must return `not-fallback`; (v) status-prefix missed when message carries provider prefix (`OpenRouter (402): …`) → strip prefix handling, must redden.

**A2. `shouldSwitch(state, classification, now) → {action:"switch"|"cooldown"|"hold", reason}`** — pure one-shot/cooldown edge (copy monitor `evaluateMonitor` one-shot discipline, `monitor-core.ts:150-200`).
- State: `{switchedThisEpisode: boolean, episodeId: string, providerCooldownUntil: Record<providerId, ts>, switchCount: number}`. Rules: one switch per episode (`agent_settled` or `/fallback reset` opens a new episode); `billing-exhaustion/auth` → `switch` if !switchedThisEpisode else `hold`; `throttle` → `cooldown` (no model switch); per-provider `cooldownMs` from PKG-C config, clock injected.
- AC: second billing failure in same episode holds (no switch loop); cooldown expiry re-arms. Gate: same test file + injected-clock tests (no real timers).
- Tests: (i) double-switch loop → remove `switchedThisEpisode` guard, must redden; (ii) cooldown ignored → zero the clock, must redden; (iii) throttle triggers model switch → must redden (throttle must be cooldown-only).

**A3. Kill-switch + caps pure helpers** — `isDisabled(env)`, `clampCooldownMs`, 8KB notice-cap helper (copy monitor `capTail`/`MONITOR_EVENT_CAP_CHARS`, `monitor-core.ts:220-280`; subagent `NOTIFICATION_CAP_CHARS` precedent). Env names: `PI_BADGER_ROUTER_FALLBACK=0` (master off), `PI_BADGER_ROUTER_FALLBACK_MAX_SWITCHES` (default 1/episode). Read per-call in PKG-B, decided here.
- AC: `=0` forces `hold` with reason naming the knob. Gate: unit test with injected env record.
- Tests: (i) kill-switch ignored → hardcode enabled, must redden.

**Seam to PKG-C:** PKG-A exports only `classifyFailure` + `shouldSwitch` + cap/kill helpers. PKG-C owns provider ordering, `registerProvider` calls, `models.json` overrides, and what "next target" means. PKG-A never imports provider code.

## 5. What I rejected (and why)

1. **Mid-stream `setModel` from `message_end`** — rejected: races `_handlePostAgentRun` retry/`continue()` (`agent-session.js:788-808`); H4 untested. Act at `agent_end`/settled/command.
2. **Rewriting `message_end` error→stop to suppress retry** — rejected: H3 unproven (`_replaceMessageInPlace` + same-role rule suggest it *might* work, but no test proves the retry check sees the replacement). React (switch + notice), don't rewrite.
3. **Exact-JSON / exact-`error_type` matching** — rejected: bodies truncate at 4000 chars, SDKs fold/prefix (`"<status>: <body>"`), OpenRouter 402 wording is HYPOTHESIS. Substring + status-prefix only.
4. **Separate SSE/200-with-error scanner** — rejected as redundant: `openai-completions.js:497-527` already folds stream/body errors into `errorMessage`. Scan the folded message only.
5. **Pinning the `:free` model list** — rejected: pool churns (d-487: 19 `:free` of 431, "availability changes frequently"). Runtime `/models` filter belongs to PKG-C.
6. **Persisting the fallback (`persist:true`) / confirming via UI** — rejected: fallback is session-only by requirement; `pi.setModel` path has no confirmation gate anyway.
7. **New event bus** — rejected: reuse `pi.events.emit/on` with a `router-fallback` transition name (subagent `TRANSITION_CHANNEL` precedent).
